# Z-Image 提示词

`references/` 里的文件来自 Tongyi-MAI 官方 HF Space [Z-Image-Turbo](https://huggingface.co/spaces/Tongyi-MAI/Z-Image-Turbo), 取于 2026-09-27, 未改动; 许可说明见 `NOTICE`。本文件是自写的调用说明。

| 文件 | 内容 |
|---|---|
| `references/pe.py` | 官方 PE 模板原文(commit 9baf60e, Tongyi-MAI 成员上传)。团队在 HF 讨论区 #8 推荐的用法是: 先自己写提示词, 再交给 LLM 按这个模板扩写 |
| `references/space-examples.md` | 官方 Space 的 7 条示例提示词原文(中文 3 条、英文 2 条、中文海报 2 条), 长度 35–1371 字符 |

官方 Space 的做法: 把用户需求代入模板里的 `{prompt}`, 整段作为 system 消息, 交给 qwen3-max-preview(temperature 0.7, top_p 0.8)。本 skill 让 Claude 读同一段模板来当扩写器。ComfyUI 里没有官方 PE 节点, 所以这就是本地流程里的 PE 步骤。Claude 不是官方用的那个模型, 效果要实测对比。

Z-Image 官方**没有** skill(Tongyi-MAI 的 GitHub 和 HF 组织都查过, 2026-09-27)。社区的几个 skill 要么 star 少, 要么只调 API 出图, 都没有引入。

## 1. 先认变体

| | Z-Image-Turbo | Z-Image(社区叫 Base) |
|---|---|---|
| 性质 | 8 次前向的蒸馏模型 | 未蒸馏的底模, 适合微调 |
| 提示词 | 长而细最好(团队回复) | 同一套 PE |
| 负面提示词 | **没用**: 不走 CFG, 团队原话是「根本不用负面提示词」 | **强烈推荐**(官方 README) |
| 采样 | diffusers 9 步(实际 8 次前向)、guidance 0 | CFG 3–5、28–50 步; `cfg_normalization` 偏风格化设 False, 偏写实设 True |

用户没说用哪个时, 默认 Turbo。

## 2. 扩写规则速查(以 `pe.py` 原文为准)

先读 `references/pe.py` **全文**, 按它的四步顺序执行:

1. **锁定不能变的核心要素**: 主体、数量、动作、状态, 以及用户指定的 IP 名称、颜色、文字。这些必须原样保留。
2. **判断要不要「生成式推理」**: 用户要的不是一个现成场景, 而是要你给方案(回答「是什么」、做「设计」、演示「怎么解题」)时, 先在脑子里想出一个完整、具体、画得出来的方案, 再往下写。
3. **加美学与真实感细节**: 构图、光影氛围、材质质感、配色方案、空间层次。
4. **处理文字(最关键的一步)**:
   - 画面里要出现的文字一字不差地写出来, 用英文直双引号 `"..."` 括起来(`pe.py` 原文就是 ASCII 的 `"`, 不要用中文弯引号 `“”`)。
   - 海报、菜单、UI 这类设计图, 要写全所有文字, 并说明字体和排版。
   - 招牌、路标、屏幕上的文字, 写明内容、位置、尺寸和材质。
   - 推理时自己加的带字元素(图表、解题步骤等)同样照此处理。
   - 画面里没有文字, 就把篇幅全用在视觉细节上, 不要硬加文字。

另外两条硬性要求:

- 描述要客观、具象: 不用比喻和情感化修辞, 不写「8K」「杰作」这类元标签, 也不写绘制指令。
- 只输出最终的提示词本身。

## 3. 语言与长度

- **语言**: `pe.py` 用中文写成, 但没规定输出语言; 官方示例中英文都有, README 的 Base 示例是中文。所以**默认跟随用户的语言**, 画面里的文字保留原文。社区有人说扩写成英文效果更好, 没有证实; 用户在意时, 用同一个 seed 各出一张对比。
- **写法**: 官方中文示例基本是「主体与动作 → 人物 / 物件逐个写细节 → 背景 → 文字逐条写位置与字体 → 风格、光线、色调、景深收尾」。README 的 Base 示例最后还缀了一串逗号短语(`照片，自然光照明，柔和阴影，…`)。这是从示例里归纳的, 官方没有规定。
- **长度上限**:
  - diffusers 默认 `max_sequence_length=512`, 超出部分被截掉, 本地可调到 1024(团队回复; 按每 token 约 0.75 个英文词估算, 512 token 约 380 个英文词)。
  - 阿里云 API 限 800 字符。
  - ComfyUI 的 `lumina2` 编码是否也截在 512, 待核实。官方最长的示例是 1371 个字符的英文和 826 个字符的中文, 可以当作安全长度的参照。

## 4. 交付格式

````
**变体**: Turbo / Base
**尺寸**: 1280×720 (16:9, 1024 档)
**提示词**:
```text
(一段)
```
**负面提示词**: (仅 Base; Turbo 写「不适用」)
**说明**: 一两句关键取舍, 比如锁定了哪些要素、补了什么、有没有做生成式推理
````

### 分辨率

官方 Space 的分辨率表分三档, 每档 11 种比例:

| 比例 | 1024 档 | 1280 档 | 1536 档 |
|---|---|---|---|
| 1:1 | 1024×1024 | 1280×1280 | 1536×1536 |
| 9:7 / 7:9 | 1152×896 / 896×1152 | 1440×1120 / 1120×1440 | 1728×1344 / 1344×1728 |
| 4:3 / 3:4 | 1152×864 / 864×1152 | 1472×1104 / 1104×1472 | 1728×1296 / 1296×1728 |
| 3:2 / 2:3 | 1248×832 / 832×1248 | 1536×1024 / 1024×1536 | 1872×1248 / 1248×1872 |
| 16:9 / 9:16 | 1280×720 / 720×1280 | 1536×864 / 864×1536 | 2048×1152 / 1152×2048 |
| 21:9 / 9:21 | 1344×576 / 576×1344 | 1680×720 / 720×1680 | 2016×864 / 864×2016 |

Base 官方给的范围是总像素 512² 到 2048², 比例任意(README)。

### 负面提示词(仅 Base)

官方只说「强烈推荐」, README 示例留空, 也没给过官方的负面词表。所以只写**用户明确不想要的东西**和本次需求的常见失败点(比如多余的手指、画面里多出不该有的文字), 不要默认套一长串通用负面词。

## 5. 本地 ComfyUI 怎么对应

- **模板**: `image_z_image_turbo`、`image_z_image`, 以及两者的 `_int8` 版; 另有 `image_z_image_turbo_fun_union_controlnet`。
- **通用设置**: CLIPLoader 的 type 选 `lumina2`, 文本编码器 `qwen_3_4b`; `ModelSamplingAuraFlow` shift 3; VAE 用 `ae`。
- **Turbo**: 8 步、cfg 1、`res_multistep` / `simple`。负面条件接的是 `ConditioningZeroOut`, 写了负面提示词也不生效。
- **Base**: 模板默认 25 步、cfg 4, 负面是普通文本框, 默认留空; 模板注释建议 30–50 步、cfg 3–5。
- **GGUF**: 本机的 Base 是 GGUF(Q4_K_M), 要把 UNETLoader 换成 ComfyUI-GGUF 的 `Unet Loader (GGUF)`, 并按 Base 参数跑, 不能套 Turbo 的 8 步 cfg 1。
- **ControlNet**: 阿里 PAI 的 Fun ControlNet Union 由 `ModelPatchLoader` 加载, 文件要放在 `models/model_patches/`, 放在 `loras/` 下模板里选不到它。
- 本机文件和踩坑见 `models/z-image.md`。
